2. 變更摘要

本分支新增應用端一致機率取樣器，讓「僅有 span link、沒有 parent」的非同步消費者 （NATS / Mongo decode / WebSocket 等）能沿用與 remote parent 相同的 randomness 種子， 避免 producer / consumer 在部分取樣下決策分叉。

主要交付

  • otel-sampler/otelsampler： ProbabilitySampler / ProbabilitySamplerFromEnv （對齊 OpenTelemetry Go PR #8123 的 threshold + ot=th: / ot=rv: 語意）， 以及 WithSingleLinkSeed 輸入適配器。
  • otel-testkit/harness：黑箱驗證工具與 ConsistentSampler = WithSingleLinkSeed(ProbabilitySampler(...))。
  • Mongo v2 / NATS sampling E2E、httpdirect 範例、CI 矩陣（含 feature-flag × sampler-arg 列）。
  • OpenSpec change：openspec/changes/use-span-link-sampler-arg-like-parent-span/。

關鍵設計不變式（已在程式與 spec 對齊）

  • Wrapper 只改取樣輸入（與結果 tracestate 的 rv），不改 SDK 建立出的 parentage / links；linked root 仍有新的 TraceID。
  • 有 valid parent 時，link 不用於 seed；恰好 1 個 valid link 才 seed；0 或多個 valid link 則 fallback 到目前 TraceID，但仍為 root 寫 ot=rv:。
  • Drop 路徑：ProbabilitySampler 不寫 th；WithSingleLinkSeed 仍可寫 rv（讓較高取樣率的下游可一致）。

P1Mongo sampling E2E 仍呼叫已更名的 DecodeWithContext（編譯失敗）

Critical 信心 100 正式成立
標記原因
CLAUDE.md API 指引 + 歷史 rebase 遺漏 + 既有 PR #25 遷移契約；實際 compile break
影響模組
otel-mongo/v2/tests/integration/sampling、CI integration-test（mongo v2 列）、sampling-e2e
相關連結
sampling_test.go#L86-L88 · cursor.go DecodeAndTrace · PR #25 · CLAUDE.md

問題說明

main 已在 0.8.0 / PR #25 完成 breaking rename： DecodeWithContext → DecodeAndTrace （v1 與 v2 的 Cursor / ChangeStream）。 本分支 rebase 到該 base（a2ab775）後， sampling E2E 仍呼叫舊名稱，導致套件無法編譯。

CLAUDE.md 目前明文要求使用 Cursor.DecodeAndTrace （不再存在 DecodeWithContext 公開 API）。

錯誤程式（現況）
// otel-mongo/v2/tests/integration/sampling/sampling_test.go:87
rctx, err := cur.DecodeWithContext(ctx, &decoded)
require.NoError(t, err)
正確 API（現行 facade）
// otel-mongo/v2/cursor.go
func (c *Cursor) DecodeAndTrace(ctx context.Context, val any) (context.Context, error) {
    return c.impl.DecodeAndTrace(ctx, val)
}

為何會在實務中踩到

  1. go test ./... 於 otel-mongo/v2/tests/integration 會編譯 sampling 套件 → 立即失敗。
  2. CI job integration-test（matrix 含 mongo v2）與 sampling-e2e 都會碰到此路徑。
  3. 本分支正是要證明 span-link + consistent sampling 的 E2E；編譯不過等於核心驗證鏈斷裂。
根因歸類：rebase / 合併 main 後未完成 API rename 的 call-site 掃蕩。 PR #25 的 OpenSpec 任務曾要求 grep -r DecodeWithContext 在 .go 中應為空； 本分支重新引入了唯一殘留。

最佳反應（Recommended fix）

  1. 將 sampling_test.go 中所有 DecodeWithContext（程式與註解）改為 DecodeAndTrace。
  2. 同步修正 otel-testkit/README.md 中的舊名稱（見 S4；建議同一 commit）。
  3. 在模組目錄驗證： 
    cd otel-mongo/v2/tests/integration
go test -c -o /dev/null ./sampling/
# 或完整：
go test -race -timeout 600s -run TestMongo ./sampling/
  4. 再跑一次全庫 grep，確保 *.go 不再出現 DecodeWithContext（archive/CHANGELOG 歷史敘述可保留）。

S1通用 integration-test 與專用 sampling E2E 重複執行

High 信心 75 次要
標記原因
歷史 CI 結構 + 本分支把重型 sampling 套件嵌在 integration 模組路徑下
位置
ci.yml#L86-L88 · sampling-e2e · nats-sampling-e2e

問題說明

integration-test 對每個 integration 模組執行 go test -v -race -timeout 300s ./...， 會一併編譯/執行 ./sampling。 同時又有 sampling-e2e / nats-sampling-e2e 以 env 矩陣（600s）再跑一次。

sampling 套件刻意獨立 package，是為了避免 parent package TestMain 強制開啟 tracing flags； 因此在「無矩陣 env」的通用 job 中，行為是 default-off 路徑， 與 dedicated job 的旗標矩陣目的不同，造成：

  • Docker 重型測試雙倍成本；
  • timeout 300s 對 full sampling suite 偏緊（專用 job 用 600s）；
  • P1 的編譯錯誤會同時炸掉「一般整合」與「sampling E2E」兩條線。
現況 CI 片段
- name: Integration Tests
  run: go test -v -race -timeout 300s ./...
  working-directory: ${{ matrix.module }}

# 另有：
# go test -race -timeout 600s -run TestMongo ./sampling/
# go test -race -timeout 600s -run TestNats ./sampling/

最佳反應

  1. 從通用 integration job 排除 sampling 套件，例如： 
    go test -v -race -timeout 300s $(go list ./... | grep -v '/sampling$')
    或把 sampling 移到獨立 module path / 使用 build tag。
  2. 保留 dedicated matrix jobs 作為唯一的 flag × rate 驗證入口。
  3. Makefile 對齊同樣排除規則，避免本地 make test-integration 意外重跑。

F1ExpectedSampled 與真實 threshold 的精度差（理論邊界）

Low 信心 25 濾除

Agent #5 指出 simpleThreshold 不做 hex precision rounding， 而 ProbabilitySampler 會。理論上邊界 rv 可能預測錯誤。

覆核結果：目前 E2E 使用的 rate 集合 {0.9, 0.5, 0.1} 與 ladder {0, 1<<53, 1<<55, max, 2<<53, 5<<53, 3<<54} 零分歧。註解也要求選「離 threshold 有大 margin 的 rv」。 因此不視為會在現況測試中爆掉的 bug。

若要預防未來回歸

  1. 加一個 unit test：對一組 (p, rv) 同時跑 ExpectedSampled 與真實 ProbabilitySampler.ShouldSample。
  2. 或讓 harness 匯出與 sampler 相同的 threshold 計算（接受重複，或抽 shared 內部 helper）。
  3. 第三輪補充：根因已在 N11(c) 定位 —— otel-testkit 其實已經 require 了 otel-sampler （harness/sampler.go），卻在 harness/flags.go 另寫一套 simpleThreshold。從 otelsampler 匯出 Threshold(p) / Sampled(p, rv) 可一次解掉， 並讓「必須挑遠離門檻的 rv」這個隱性測試前提消失。

Medium 信心 75 新增成立
位置

WaitForAppSpans 的 predicate 是 len(...) >= want。 當 want == 0 時,predicate 在第一次求值就成立, sink.WaitFor 立刻回傳、完全不等待。 接著 AssertAppSpanCounts(…, rv=0, 1) 對一個「還沒來得及收到任何東西」的 sink 斷言「每個 service 都是 0 個 span」。
