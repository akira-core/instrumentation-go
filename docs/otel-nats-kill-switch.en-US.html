otel-nats × kill-switch relay-proxy tutorial

Step-by-step guide to wire otel-nats (v0.8.0+) to a GO Feature Flag relay proxy via OpenFeature, so operators can toggle NATS tracing on or off at runtime — no redeploy. Covers the zero-code env path and installing your own provider.

Sections: Overview → Ladder → Switches → Tri-state → Quickstart → Env → Provider → WithTracingEnabled → TracerProvider → Usage → Relay flag → Toggle → Targeting → Latency → Cheatsheet → Pitfalls

1. Overview

otel-nats is OpenTelemetry instrumentation for NATS / JetStream. It does not initialize a TracerProvider; the application sets the global provider / propagator. From 0.8.0, every switch resolves down a four-rung ladder. A relay at the top is authoritative in both directions: it can disable a running module and enable one the deployment left off.

  • Deployer sets env vars (or WithTracingEnabled) for the resting state.
  • Operator flips relay flag otel-nats-tracing without restarting.
  • With no relay configured, behavior is decided by env + option + defaults only — no OpenFeature cost.
One line: Safety comes from the defaults (module default false; master default true is a veto, not an enabler), not from locking the relay to revoke-only.

Full reference (all modules, tables, Mongo propagation risk): feature-flags.md.

2. Precedence ladder

relay > env > option (With*Enabled) > hardcoded default
Source Owner Scope Change without redeploy?
relay operator fleet or one service Yes — the only one
env deployer one process No
option caller constructing the wrapper one connection No
default library everywhere nobody spoke No
The option sits below its env var. OTEL_NATS_TRACING_ENABLED=false wins over WithTracingEnabled(true). Supplying both is legal; there is no ErrTracingConfigConflict.

3. The three switches

Switch Relay key Env Option Default
master otel-instrumentation-go-tracing OTEL_INSTRUMENTATION_GO_TRACING_ENABLED — true (veto)
NATS tracing otel-nats-tracing OTEL_NATS_TRACING_ENABLED WithTracingEnabled false
tracing = master && moduleTracing

Master is a veto, not an enabler. Default true means “no objection”. Setting it true changes nothing; only false stops every module. Creating otel-instrumentation-go-tracing: true on a relay does nothing useful.

Nothing turns on because the master is true. The module default of false keeps a zero-config process silent.

Worked examples

ConfigurationResult
nothing setoff
OTEL_INSTRUMENTATION_GO_TRACING_ENABLED=true onlyoff — master enables nothing
OTEL_NATS_TRACING_ENABLED=true onlyon — master defaults true
WithTracingEnabled(true), no envon for that connection
WithTracingEnabled(true) + OTEL_NATS_TRACING_ENABLED=falseoff — env outranks option
relay otel-nats-tracing: true, module env unseton — relay can enable
relay otel-nats-tracing: false, module env trueoff — relay can disable
master env false + everything else onoff — veto wins

4. Environment values are a strict tri-state

ValueOutcome
unsetno opinion — fall through to option, then default
1 / true / yes / onthis source decides (on)
0 / false / no / offthis source decides (off)
anything else, including empty stringconstruction error wrapping otelflags.ErrInvalidFlagValue
export VAR= is invalid, not falsy. Audit every OTEL_*_ENABLED value before upgrading — unexpanded ${SOMETHING} templates hit this case and fail construction.

5. Quickstart (zero-code relay)

Most common path: set environment variables only. The library auto-installs a GOFF provider on OpenFeature domain otel-instrumentation-go when OTEL_INSTRUMENTATION_GO_FLAGS_ENDPOINT is set and no provider is already bound. No OpenFeature code in the application.

Deploy the relay proxyops

Run a GO Feature Flag relay (default port 1031) with a flag config that includes otel-nats-tracing.

Choose a resting stateenv

# Example: deploy with NATS tracing on; relay can flip either way
OTEL_NATS_TRACING_ENABLED=true

# Optional process-wide veto (default is already true / no objection)
# OTEL_INSTRUMENTATION_GO_TRACING_ENABLED=true

Or leave the module env unset (default off) and enable later via relay — that also works.

Point at the relayenv

OTEL_INSTRUMENTATION_GO_FLAGS_ENDPOINT=http://relay-proxy:1031

# Optional
OTEL_INSTRUMENTATION_GO_FLAGS_API_KEY=...          # if relay auth is on
OTEL_INSTRUMENTATION_GO_FLAGS_POLL_INTERVAL=60s    # Go duration only; default 60s
OTEL_SERVICE_NAME=my-service                      # for targeting

Unset FLAGS_ENDPOINT ⇒ no provider, no OpenFeature path.

Set TracerProvider at startupcode

See §9. Then connect:

conn, err := otelnats.Connect(natsURL /* nats.Option... */)

Define the relay flagops

otel-nats-tracing:
  variations:
    enabled: true
    disabled: false
  defaultRule:
    variation: enabled   # or disabled — resting state is yours

7. Install your own OpenFeature provider

Use this when you need lifecycle control, a shared provider with business flags, or a blocking wait until ready (closes the startup window). Install before constructing any wrapper — relayPossible is fixed at construction.

Install before wrapperscode

import (
    gofeatureflag "github.com/open-feature/go-sdk-contrib/providers/go-feature-flag/pkg"
    "github.com/open-feature/go-sdk/openfeature"

    otelflags "github.com/akira-core/instrumentation-go/otel-flags"
)

provider, err := gofeatureflag.NewProvider(gofeatureflag.ProviderOptions{
    Endpoint:              "http://relay-proxy:1031",
    DataCollectorDisabled: true, // required — see below
})
if err != nil {
    // Log and continue — relay is not a hard dependency
    logger.Error("feature flag provider unavailable", "error", err)
} else if err := openfeature.SetNamedProviderAndWait(
    otelflags.FlagDomain, provider,
); err != nil {
    logger.Error("feature flag provider registration failed", "error", err)
}

Do not also set FLAGS_ENDPOINTenv

When you install yourself, leave OTEL_INSTRUMENTATION_GO_FLAGS_ENDPOINT unset so the auto-install stands down cleanly.

Hard rules

RuleWhy
DataCollectorDisabled: true Default collector can stall every NATS publish behind a failed flush when the relay is down. Zero-code path hardcodes this off.
In-process evaluation only Remote evaluation puts HTTP on every instrumented operation.
Named domain otel-instrumentation-go Use SetNamedProviderAndWait, not the default provider.
Provider before wrappers A wrapper built too early resolves statically for life and never consults the relay.

Startup window

Zero-code install is non-blocking. Until the first successful fetch, every switch resolves to its local value (env / option / default). That is fail-safe: the window can delay a relay-driven enable; it cannot introduce one.

8. WithTracingEnabled

Supplies the module tier for one connection — below its env var, above the hardcoded default, far below the relay. It does not pin anything: the connection still resolves master + relay on every operation. 

conn, err := otelnats.ConnectWithOptions(url, nil,
    otelnats.WithTracingEnabled(true),
)
// Legal alongside OTEL_NATS_TRACING_ENABLED — the env var wins if set.

Accepted by:

  • otelnats.ConnectWithOptions
  • otelnats.ConnectTLSWithOptions
  • otelnats.ConnectWithCredentialsWithOptions
Subscriptions and JetStream consumers re-resolve per message, so a flag change reaches them without re-establishing the subscription.

9. TracerProvider and Propagator

Per OTel Go Contrib: the package accepts TracerProvider / Propagators via options; it does not provide InitTracer. Defaults to otel.GetTracerProvider() / otel.GetTextMapPropagator(). 

import (
    "go.opentelemetry.io/otel"
    "go.opentelemetry.io/otel/propagation"
)

tp, err := newTracerProvider() // your OTLP + resource setup
if err != nil { log.Fatal(err) }
defer tp.Shutdown(ctx)

otel.SetTracerProvider(tp)
otel.SetTextMapPropagator(propagation.NewCompositeTextMapPropagator(
    propagation.TraceContext{},
    propagation.Baggage{},
))

conn, err := otelnats.ConnectWithOptions(url, nil,
    otelnats.WithTracerProvider(tp),
    otelnats.WithPropagators(otel.GetTextMapPropagator()),
)

Runnable example: otel-nats/examples/.

10. otel-nats basic usage

Core NATS

import "github.com/akira-core/instrumentation-go/otel-nats/otelnats"

conn, err := otelnats.Connect(natsURL)
if err != nil { log.Fatal(err) }
defer conn.Close()

_ = conn.Publish(ctx, "subject", []byte("data"))

_, _ = conn.Subscribe("subject", func(m otelnats.Msg) {
    ctx := m.Context() // extracted trace; thread into downstream calls
    _ = ctx
})

JetStream

import "github.com/akira-core/instrumentation-go/otel-nats/oteljetstream"

js, err := oteljetstream.New(conn)
// after CreateOrUpdateStream / Consumer:
cons.Consume(func(m oteljetstream.Msg) {
    ctx := m.Context()
    _ = m.Ack()
    _ = ctx
})

11. Relay flag definition

otel-nats-tracing:
  variations:
    enabled: true
    disabled: false
  defaultRule:
    variation: enabled
  • enabled (true) = allow tracing (when lower rungs also allow).
  • disabled (false) = stop span production; NATS message path still runs.
  • Master key otel-instrumentation-go-tracing exists to veto the whole process — set it false, never create it as true expecting an enable.

All four modules share domain otel-instrumentation-go:

Relay flagPaired envModule
otel-instrumentation-go-tracingOTEL_INSTRUMENTATION_GO_TRACING_ENABLEDall (veto)
otel-nats-tracingOTEL_NATS_TRACING_ENABLEDotel-nats
otel-mongo-tracingOTEL_MONGO_TRACING_ENABLEDotel-mongo / v2
otel-mongo-propagationOTEL_MONGO_PROPAGATION_ENABLEDotel-mongo / v2
otel-gorilla-ws-tracingOTEL_GORILLA_WS_TRACING_ENABLEDotel-gorilla-ws

12. Hot toggle (both directions)

Confirm relay is reachable

FLAGS_ENDPOINT set (or your own provider installed before wrappers), and wrappers already constructed.

Flip the flagops

# Disable NATS tracing
defaultRule:
  variation: disabled

# Re-enable
defaultRule:
  variation: enabled

Wait for the provider poll

Latency ≈ relay config reload + provider poll interval. Production default poll: 60s.

Verify

  • NATS publish / subscribe / reply still run
  • New NATS PRODUCER / CONSUMER spans appear or stop as expected
Relay can enable. If the deployment left the module off (env unset / default), setting the flag to enabled turns tracing on within the poll interval — by design. Sites that cannot accept that keep OTEL_INSTRUMENTATION_GO_FLAGS_ENDPOINT unset, or set the master veto / module env to false (env outranks application options; relay still outranks env when a provider is bound).

13. Targeting one service

otel-nats-tracing:
  variations:
    enabled: true
    disabled: false
  targeting:
    - query: service.name eq "checkout-api"
      variation: disabled
  defaultRule:
    variation: enabled
  • Zero-code path sends service.name from OTEL_SERVICE_NAME.
  • Self-installed provider: set evaluation context yourself.
  • Process-level only — no per-request targeting.

14. Change latency

SourceDelay
Module resolutionnone — every operation reads the current value
Provider poll (zero-code)up to OTEL_INSTRUMENTATION_GO_FLAGS_POLL_INTERVAL (default 60s)
Provider poll (self-install)whatever you set; GOFF default often 120s

Plan incident response around the poll interval in both directions. Polls are conditional GETs (304 when unchanged); tightening is cheap.

15. Ops cheatsheet

GoalAction
Make NATS relay-controllable Set FLAGS_ENDPOINT + create otel-nats-tracing. No app code.
Stop NATS tracing now Relay flag → false / disabled. Wait one poll.
Start NATS tracing now Relay flag → true / enabled. Wait one poll.
Stop one service OTEL_SERVICE_NAME + service.name targeting.
Stop the whole process Master relay otel-instrumentation-go-tracing: false, or env OTEL_INSTRUMENTATION_GO_TRACING_ENABLED=false + redeploy.
Stop one module without relay OTEL_NATS_TRACING_ENABLED=false + redeploy. App options cannot override.
Close the startup window SetNamedProviderAndWait before constructing wrappers.
No relay at all Leave FLAGS_ENDPOINT unset. Env + option + defaults only.

16. Common pitfalls

  1. export VAR= or enabled / 2 → construction error. Use only the allow-list.
  2. POLL_INTERVAL=60 (no unit) → rejected; use 60s.
  3. Self-install without DataCollectorDisabled: true → relay outage can stall NATS paths.
  4. Install provider after constructing wrappers → those wrappers never see the relay.
  5. Expecting master true to enable something → it does not.
  6. Expecting an immediate flip → budget the poll interval (default 60s).
  7. Assuming option beats env → reversed vs 0.7.0; env wins.
