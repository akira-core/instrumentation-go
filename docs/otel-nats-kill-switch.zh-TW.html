otel-nats 與 kill-switch relay-proxy 使用指南

逐步說明如何把 otel-nats（v0.8.0+）接到 GO Feature Flag relay proxy， 用 OpenFeature 做只能撤銷、不能開啟的動態 tracing 煞車。 涵蓋環境變數零程式碼路徑，以及自行安裝 provider 的完整做法。

本頁章節： 總覽 → 三層模型 → 快速開始 → 環境變數 → 自行裝 Provider → WithTracingEnabled → TracerProvider → 用法 → Relay flag → 熱撤銷 → Targeting → 延遲 → Demo → 速查 → 陷阱

1. 總覽

otel-nats 是 OpenTelemetry 對 NATS / JetStream 的 instrumentation。 它不自行初始化 TracerProvider；應用負責設全域 provider / propagator。 從 0.8.0 起，tracing 可由三層開關共同決定，其中第三層透過 relay proxy 在執行期撤銷。

  • 部署者用環境變數（或 WithTracingEnabled）打開 tracing。
  • 維運者用 relay flag otel-nats-tracing 緊急關掉 span 產出，無需重啟。
  • Relay 永遠無法打開任何東西；沒裝 provider 時行為完全由環境決定。
一句話：Instrumentation 由部署啟用，由維運者撤銷。 Relay 只是緊急煞車，不是功能開關面板。

2. 三層開關模型

tracing = gate1 && OTEL_NATS_TRACING_ENABLED && relay(otel-nats-tracing)
層 來源 擁有者 關掉時 不重部署能改？
gate1 OTEL_INSTRUMENTATION_GO_TRACING_ENABLED 或 WithTracingEnabled(v)（互斥） 部署者 / 呼叫端 整 process 只建 passthrough，不碰 OpenFeature 否
模組 env OTEL_NATS_TRACING_ENABLED 部署者 NATS 模組 passthrough；relay 永不被查詢 否
relay OpenFeature key otel-nats-tracing 維運者 下次操作起停止產出 span 可以 — 只有這一層

有效 tracing 真值表

gate1 OTEL_NATS_TRACING_ENABLED relay Tracing 有問 relay？
停用任何任何關否
啟用未設 / falsy任何關否
啟用truthyfalse關是
啟用truthytrue / 沒有意見開是
「沒有意見」= 允許。 Evaluation default 是 true。沒裝 provider、provider 未 ready、 key 不存在、評估錯誤、relay 不可達且無快取 —— 全部視為「不要干涉」，由環境決定。

3. 真值判定

只有設成以下四個字（先轉小寫、去頭尾空白）才算啟用：

1 · true · yes · on

4. 快速開始（零程式碼連上 relay）

最常見路徑：設環境變數即可。Library 在第一次 instrumented operation 自動建立 GOFF provider，綁到 OpenFeature domain otel-instrumentation-go。 應用不必寫任何 OpenFeature 程式碼。

部署 relay proxy維運

使用 GO Feature Flag relay（本 demo 用 Helm chart charts/relay-proxy/， 預設埠 1031），並讓它讀取含 otel-nats-tracing 的 flag 設定 （例如 Kubernetes ConfigMap）。

開啟兩層環境開關環境

OTEL_INSTRUMENTATION_GO_TRACING_ENABLED=1
OTEL_NATS_TRACING_ENABLED=1

指向 relay環境

OTEL_INSTRUMENTATION_GO_FLAGS_ENDPOINT=http://relay-proxy:1031

# 可選
OTEL_INSTRUMENTATION_GO_FLAGS_API_KEY=...          # relay 有認證時
OTEL_INSTRUMENTATION_GO_FLAGS_POLL_INTERVAL=60s    # 預設 60s；demo 可用 2s
OTEL_SERVICE_NAME=my-service                      # 供 targeting 用

未設 FLAGS_ENDPOINT ⇒ 不安裝任何 provider，行為完全由環境決定。

應用啟動時設 TracerProvider程式碼

見 §8。然後用 otelnats.Connect 連線即可。

conn, err := otelnats.Connect(natsURL /* nats.Option... */)
// 不要同時傳 WithTracingEnabled —— 已用 env 供給 gate1

確認 relay flag 預設為「不撤銷」維運

otel-nats-tracing:
  variations:
    enabled: true
    disabled: false
  defaultRule:
    variation: enabled   # 「不干涉」；改 disabled 即 kill

5. 環境變數完整表

Tracing 閘門

Flag key 與環境變數的配對是慣例：環境變數是獨立的、需同時成立的層級， 不是 relay flag 的 evaluation default。

6. 自行安裝 OpenFeature Provider

當你需要生命週期控制、與業務 flag 共用 provider、或要阻塞等待 ready （關掉啟動窗口）時，自行安裝。Library 偵測到 domain / default 已有 provider 就會完全讓路。

在建構任何 wrapper 之前安裝程式碼

import (
    gofeatureflag "github.com/open-feature/go-sdk-contrib/providers/go-feature-flag/pkg"
    "github.com/open-feature/go-sdk/openfeature"
)

provider, err := gofeatureflag.NewProvider(gofeatureflag.ProviderOptions{
    Endpoint:              "http://relay-proxy:1031",
    DataCollectorDisabled: true, // 必要 —— 見下方說明
})
if err != nil {
    return err
}

// 建議：綁到 library 使用的 named domain
if err := openfeature.SetNamedProviderAndWait(
    "otel-instrumentation-go", provider,
); err != nil {
    // 記錄後繼續。不要讓啟動失敗 —— relay 不是硬相依
    logger.Error("feature flag provider unavailable; continuing without relay",
        "error", err)
}

// 或：SetProviderAndWait(provider) 設為 default provider
// （domain otel-instrumentation-go 也會走 default）

不要同時設 FLAGS_ENDPOINT環境

已自行安裝時，請不要再設 OTEL_INSTRUMENTATION_GO_FLAGS_ENDPOINT。 它會被忽略（無害但誤導）。

自行供給 evaluation context（若要 targeting）

零程式碼路徑會自動送 service.name（來自 OTEL_SERVICE_NAME）。 自行安裝時 context 歸你管： 

openfeature.SetEvaluationContext(openfeature.NewEvaluationContext(
    "", // targeting key
    map[string]any{
        "service.name": "checkout-api",
    },
))

必要硬規則

項目為什麼
DataCollectorDisabled: true Collector 預設開。Relay 掛掉時同步 flush 會卡住評估 goroutine， 連帶拖慢 NATS publish —— 正是 kill-switch 設計要避免的。 零程式碼路徑已寫死關掉。
In-process evaluation 背景輪詢、本地評估。Remote evaluation 會把 HTTP 塞進每筆 NATS 操作路徑，不支援。
Relay 不是啟動相依 Provider 第一次抓取失敗 → 記錄後繼續。中止啟動會把煞車變成硬相依。

啟動窗口

無法解析的 flag = 允許。零程式碼安裝是非阻塞的， 從安裝到第一次成功抓取之間，每個 flag 都讀作啟用。 若維運者已撤銷、process 又重啟，會短暫以 instrumented 狀態回來直到 provider 追上。

要關掉啟動窗口：在建構任何 otelnats wrapper 之前， 用 SetProviderAndWait / SetNamedProviderAndWait 自行安裝。

7. 用 WithTracingEnabled 供給 gate1

無法設 process 環境變數時（測試、同一 binary 多組 client）， 可用建構選項供給 gate1。它與 OTEL_INSTRUMENTATION_GO_TRACING_ENABLED 是同一開關的兩種拼法， 只能設一個 —— 即使兩者一致也是建構錯誤。

ENV WithTracingEnabled gate1
未設未傳停用
未設true啟用
未設false停用
truthy未傳啟用
falsy未傳停用
已設（任何值）已傳（任何值）建構錯誤
 
conn, err := otelnats.ConnectWithOptions(url, nil,
    otelnats.WithTracingEnabled(true),
)
if errors.Is(err, otelnats.ErrTracingConfigConflict) {
    // 環境變數也設了 —— 拿掉其中一個
}
WithTracingEnabled 不會讓連線豁免於撤銷。 它只供給 gate1；模組 env 與 relay 仍照常運作。訂閱與 JetStream consumer 每則訊息重新解析 relay verdict，撤銷前建立的訂閱不用重建。

接受此 option 的 API：

  • otelnats.ConnectWithOptions
  • otelnats.ConnectTLSWithOptions
  • otelnats.ConnectWithCredentialsWithOptions

8. TracerProvider 與 Propagator（應用負責）

套件依 OTel Go Contrib 規範：只透過 option 接受 TracerProvider / Propagators， 不提供 InitTracer。預設用 otel.GetTracerProvider() / otel.GetTextMapPropagator()。 

import (
    "go.opentelemetry.io/otel"
    "go.opentelemetry.io/otel/propagation"
    sdktrace "go.opentelemetry.io/otel/sdk/trace"
    // ... OTLP exporter、resource
)

tp, err := newTracerProvider() // 你的 OTLP + resource 設定
if err != nil { log.Fatal(err) }
defer tp.Shutdown(ctx)

otel.SetTracerProvider(tp)
otel.SetTextMapPropagator(propagation.NewCompositeTextMapPropagator(
    propagation.TraceContext{},
    propagation.Baggage{},
))

// 可選：單一連線覆寫
conn, err := otelnats.ConnectWithOptions(url, nil,
    otelnats.WithTracerProvider(tp),
    otelnats.WithPropagators(otel.GetTextMapPropagator()),
)

完整可執行範例見 third_party/instrumentation-go/otel-nats/examples/main.go。

9. otel-nats 基本用法

Core NATS

import "github.com/akira-core/instrumentation-go/otel-nats/otelnats"

conn, err := otelnats.Connect(natsURL /* nats.Option... */)
if err != nil { log.Fatal(err) }
defer conn.Close()

_ = conn.Publish(ctx, "subject", []byte("data"))

_, _ = conn.Subscribe("subject", func(m otelnats.Msg) {
    ctx := m.Context() // 從 header 解出的 trace；傳給下游
    _ = ctx
})

JetStream

import "github.com/akira-core/instrumentation-go/otel-nats/oteljetstream"

js, err := oteljetstream.New(conn)
// CreateOrUpdateStream / Consumer 之後：
cons.Consume(func(m oteljetstream.Msg) {
    ctx := m.Context()
    _ = m.Ack()
    _ = ctx
})

其他 Connect 變體

  • ConnectTLS / ConnectTLSWithOptions — 雙向 TLS
  • ConnectWithCredentials / ConnectWithCredentialsWithOptions — JWT/NKey
  • WithTraceDestination(subject) — NATS 2.11+ Trace Events

10. Relay flag 定義

GO Feature Flag 格式範例（本 demo 的 ConfigMap）：

otel-nats-tracing:
  variations:
    enabled: true
    disabled: false
  defaultRule:
    variation: enabled
  • enabled（true）= 不撤銷，不是「打開 tracing」。
  • disabled（false）= 緊急煞車，停止 span 產出；NATS 訊息路徑仍執行。
  • gate1 沒有 relay key —— 要靜音整個 process 得逐一模組撤銷（或改 env 重部署）。

四個模組共用單一 OpenFeature domain otel-instrumentation-go：

Relay flag配對 env模組
otel-nats-tracingOTEL_NATS_TRACING_ENABLEDotel-nats
otel-mongo-tracingOTEL_MONGO_TRACING_ENABLEDotel-mongo / v2
otel-mongo-propagationOTEL_MONGO_PROPAGATION_ENABLEDotel-mongo / v2
otel-gorilla-ws-tracingOTEL_GORILLA_WS_TRACING_ENABLEDotel-gorilla-ws

11. 熱撤銷操作

確認 tracing 已由環境開啟

兩層 env 皆 truthy，且 FLAGS_ENDPOINT（或自行 provider）已接上。

把 flag 改成 disabledkill

# 本 demo
kubectl edit configmap demo-feature-flags -n demo

# 將 defaultRule.variation 改為 disabled
defaultRule:
  variation: disabled

等待 provider 輪詢

延遲 ≈ relay 重讀設定 + provider poll interval。 Demo：ConfigMap ~1s + poll 2s ⇒ 數秒內生效。 生產預設 poll 60s。

驗證

  • NATS publish / subscribe / reply 仍執行
  • 新的 NATS PRODUCER / CONSUMER span 不再出現
  • 恢復：把 variation 改回 enabled
Relay 無法「打開」tracing。 若環境關掉了 tracing，把 flag 設成 enabled 不會有任何效果。 要重新開啟：改環境變數並重新部署。

12. 針對單一服務而非整個機隊

設 OTEL_SERVICE_NAME 後，零程式碼路徑每次評估會帶 service.name 屬性： 

otel-nats-tracing:
  variations:
    enabled: true
    disabled: false
  targeting:
    - query: service.name eq "demo-backend"
      variation: disabled     # 只停這個服務
  defaultRule:
    variation: enabled
  • 自行安裝 provider 時，須自己用 SetEvaluationContext 供給屬性。
  • Targeting 是 process 級（service / environment / host），不支援 per-request。

13. 撤銷延遲

來源延遲
模組自身解析無 —— 每次操作讀當下值，不做快取
Provider 輪詢（零程式碼）最多 OTEL_INSTRUMENTATION_GO_FLAGS_POLL_INTERVAL（預設 60s）
Provider 輪詢（自行安裝）由你設定；GOFF 預設常為 120s
Relay 讀 ConfigMap（本 demo）~1s（pollingInterval: 1000）

規劃事故應變以輪詢間隔為準，不是「立即」。 輪詢是帶 ETag 的 conditional GET（無變更回 304），縮短間隔成本低。

15. 維運速查

目標做法
讓模組可撤銷 開著的 gate1 + OTEL_NATS_TRACING_ENABLED + FLAGS_ENDPOINT + relay 上建立 flag。無須應用程式碼。
立刻停 NATS tracing Relay flag otel-nats-tracing → false / disabled。等下一次 poll。
只停一個服務 設 OTEL_SERVICE_NAME，relay 用 service.name targeting。
永久停掉 改環境變數並重新部署。
為了調查把 tracing 打開 Relay 做不到。改環境並重新部署。
關掉啟動窗口 啟動時 SetProviderAndWait，再建構 wrapper。
測試裡供給 gate1 WithTracingEnabled(true)；勿同時設全域 env。

16. 常見陷阱

  1. 同時設 env 與 WithTracingEnabled → ErrTracingConfigConflict，即使值相同。
  2. export VAR=enabled 或空字串 → 不算啟用。只用 1/true/yes/on。
  3. POLL_INTERVAL=60（無單位） → 被拒，退回 60s 並 warning。須寫 60s。
  4. 自行裝 provider 卻忘了 DataCollectorDisabled: true → relay 中斷可能拖住 NATS 路徑。
  5. 以為撤銷能打開 tracing → 不能。Relay 只能減，不能加。
  6. 以為撤銷是瞬間 → 以 poll interval 為準（預設最多 60s）。
  7. JS 姊妹套件 @akira-core/otel-nats → 僅有 env gate，沒有 OpenFeature / relay kill-switch。
