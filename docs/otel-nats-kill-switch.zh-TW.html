otel-nats × kill-switch relay-proxy 使用指南

逐步說明如何把 otel-nats（v0.8.0-rc.3+）接到 GO Feature Flag relay proxy， 透過 OpenFeature 在執行期 雙向切換 NATS tracing——不必 redeploy。 涵蓋零程式碼 env 路徑，以及自行安裝 provider。

本頁章節： Overview → Ladder → Switches → Tri-state → Quickstart → Env → Provider → WithTracingEnabled → TracerProvider → Usage → Relay flag → Toggle → Targeting → Latency → Cheatsheet → Pitfalls

1. Overview

otel-nats 是 NATS / JetStream 的 OpenTelemetry instrumentation。 它不自行初始化 TracerProvider；由應用設定 global provider / propagator。從 0.8.0 起，每個 switch 沿著四層 ladder 解析。 最上層的 relay 雙向有效：可以關掉正在跑的模組，也可以打開 deployment 當初沒開的模組。

  • Deployer 用 env（或 WithTracingEnabled）決定 resting state。
  • Operator 用 relay flag otel-nats-tracing 熱切換，不用重啟。
  • 沒接 relay 時，只由 env + option + default 決定——沒有 OpenFeature 成本。
一句話：安全性來自 default（module 預設 false； master 預設 true 是 veto 不是 enabler）， 不是把 relay 鎖成只能關不能開。

完整參考（所有模組、表格、Mongo propagation 風險）： feature-flags.zh-TW.md · feature-flags.md。

2. Precedence ladder

relay > env > option (With*Enabled) > hardcoded default
Source Owner Scope 不 redeploy 能改？
relay operator fleet 或單一 service 可以 — 唯一一層
env deployer 單一 process 否
option 建構 wrapper 的 caller 單一 connection 否
default library 沒人表態的地方 否
Option 排在 env 之下。 OTEL_NATS_TRACING_ENABLED=false 會贏過 WithTracingEnabled(true)。兩者同時設是合法的； 已沒有 ErrTracingConfigConflict。

3. Three switches

Switch Relay key Env Option Default
master otel-instrumentation-go-tracing OTEL_INSTRUMENTATION_GO_TRACING_ENABLED — true（veto）
NATS tracing otel-nats-tracing OTEL_NATS_TRACING_ENABLED WithTracingEnabled false
tracing = master && moduleTracing

Master 是 veto，不是 enabler。預設 true 代表 「沒有異議」。設成 true 不會改變任何事；只有 false 會關掉 process 內所有模組。在 relay 上建立 otel-instrumentation-go-tracing: true 沒有實用效果。

Master 為 true 不會打開任何東西。Module 預設 false 才讓零設定 process 保持安靜。

Worked examples

只有 OTEL_NATS_TRACING_ENABLED=trueon — master 預設 true

5. Quickstart（zero-code relay）

最常見路徑：只設環境變數。當 OTEL_INSTRUMENTATION_GO_FLAGS_ENDPOINT 有設、且尚未綁定 provider 時，library 會自動在 OpenFeature domain otel-instrumentation-go 安裝 GOFF provider。應用不必寫任何 OpenFeature 程式碼。

部署 relay proxyops

跑 GO Feature Flag relay（預設埠 1031），flag config 需包含 otel-nats-tracing。

選定 resting stateenv

# 範例：部署時 NATS tracing 開著；relay 可雙向切
OTEL_NATS_TRACING_ENABLED=true

# 可選 process-wide veto（預設已是 true / 無異議）
# OTEL_INSTRUMENTATION_GO_TRACING_ENABLED=true

或者 module env 不設（預設 off），之後用 relay enable——也可以。

指向 relayenv

OTEL_INSTRUMENTATION_GO_FLAGS_ENDPOINT=http://relay-proxy:1031

# 可選
OTEL_INSTRUMENTATION_GO_FLAGS_API_KEY=...          # relay 有認證時
OTEL_INSTRUMENTATION_GO_FLAGS_POLL_INTERVAL=60s    # 必須是 Go duration；預設 60s
OTEL_SERVICE_NAME=my-service                      # targeting 用

未設 FLAGS_ENDPOINT ⇒ 不安裝 provider，不走 OpenFeature。

啟動時設 TracerProvidercode

見 §9。然後連線：

conn, err := otelnats.Connect(natsURL /* nats.Option... */)

定義 relay flagops

otel-nats-tracing:
  variations:
    enabled: true
    disabled: false
  defaultRule:
    variation: enabled   # 或 disabled — resting state 由你決定

7. 自行安裝 OpenFeature provider

需要生命週期控制、與業務 flag 共用 provider、或要 阻塞等到 ready（關掉 startup window）時用這條路。 必須在建構任何 wrapper 之前安裝—— relayPossible 在 construction 時固定。

先裝 provider，再建 wrappercode

import (
    gofeatureflag "github.com/open-feature/go-sdk-contrib/providers/go-feature-flag/pkg"
    "github.com/open-feature/go-sdk/openfeature"

    otelflags "github.com/akira-core/instrumentation-go/otel-flags"
)

provider, err := gofeatureflag.NewProvider(gofeatureflag.ProviderOptions{
    Endpoint:              "http://relay-proxy:1031",
    DataCollectorDisabled: true, // 必要 —— 見下方
})
if err != nil {
    // 記錄後繼續 —— relay 不是硬相依
    logger.Error("feature flag provider unavailable", "error", err)
} else if err := openfeature.SetNamedProviderAndWait(
    otelflags.FlagDomain, provider,
); err != nil {
    logger.Error("feature flag provider registration failed", "error", err)
}

不要同時設 FLAGS_ENDPOINTenv

自行安裝時，請不要再設 OTEL_INSTRUMENTATION_GO_FLAGS_ENDPOINT， 讓 auto-install 乾淨讓路。

Hard rules

RuleWhy
DataCollectorDisabled: true 預設 collector 在 relay 掛掉時可能把每次 NATS publish 卡在 failed flush。 Zero-code 路徑已寫死關掉。
In-process evaluation only Remote evaluation 會把 HTTP 塞進每筆 instrumented operation。
Named domain otel-instrumentation-go 用 SetNamedProviderAndWait，不要碰 default provider。
Provider before wrappers 太早建的 wrapper 會終身靜態解析，永遠不問 relay。

Startup window

Zero-code install 是 non-blocking。在第一次成功 fetch 之前，每個 switch 落到local 值（env / option / default）。這是 fail-safe： window 只能延遲 relay-driven enable，不可能憑空引入一個。

8. WithTracingEnabled

供給module 這一層——低於 env、高於 hardcoded default、 遠低於 relay。它不會釘死任何東西：connection 每次操作仍會解析 master + relay。 

conn, err := otelnats.ConnectWithOptions(url, nil,
    otelnats.WithTracingEnabled(true),
)
// 與 OTEL_NATS_TRACING_ENABLED 同時設是合法的 —— 有設 env 就由 env 贏。

接受此 option 的 API：

  • otelnats.ConnectWithOptions
  • otelnats.ConnectTLSWithOptions
  • otelnats.ConnectWithCredentialsWithOptions
Subscription 與 JetStream consumer 每則訊息重新解析， 所以 flag 變更不必重建訂閱。

9. TracerProvider 與 Propagator

依 OTel Go Contrib：套件只透過 option 接受 TracerProvider / Propagators， 不提供 InitTracer。預設用 otel.GetTracerProvider() / otel.GetTextMapPropagator()。 

import (
    "go.opentelemetry.io/otel"
    "go.opentelemetry.io/otel/propagation"
)

tp, err := newTracerProvider() // 你的 OTLP + resource 設定
if err != nil { log.Fatal(err) }
defer tp.Shutdown(ctx)

otel.SetTracerProvider(tp)
otel.SetTextMapPropagator(propagation.NewCompositeTextMapPropagator(
    propagation.TraceContext{},
    propagation.Baggage{},
))

conn, err := otelnats.ConnectWithOptions(url, nil,
    otelnats.WithTracerProvider(tp),
    otelnats.WithPropagators(otel.GetTextMapPropagator()),
)

可執行範例：otel-nats/examples/。

10. otel-nats basic usage

Core NATS

import "github.com/akira-core/instrumentation-go/otel-nats/otelnats"

conn, err := otelnats.Connect(natsURL)
if err != nil { log.Fatal(err) }
defer conn.Close()

_ = conn.Publish(ctx, "subject", []byte("data"))

_, _ = conn.Subscribe("subject", func(m otelnats.Msg) {
    ctx := m.Context() // 從 header 解出的 trace；傳給下游
    _ = ctx
})

JetStream

import "github.com/akira-core/instrumentation-go/otel-nats/oteljetstream"

js, err := oteljetstream.New(conn)
// CreateOrUpdateStream / Consumer 之後：
cons.Consume(func(m oteljetstream.Msg) {
    ctx := m.Context()
    _ = m.Ack()
    _ = ctx
})

11. Relay flag definition

otel-nats-tracing:
  variations:
    enabled: true
    disabled: false
  defaultRule:
    variation: enabled
  • enabled（true）= 允許 tracing（較低 rung 也允許時）。
  • disabled（false）= 停止產出 span；NATS 訊息路徑仍執行。
  • Master key otel-instrumentation-go-tracing 用來 veto 整個 process——設 false， 不要建立 true 期待它會 enable。

四個模組共用 domain otel-instrumentation-go：

otel-instrumentation-go-tracingOTEL_INSTRUMENTATION_GO_TRACING_ENABLEDall（veto）
otel-nats-tracingOTEL_NATS_TRACING_ENABLEDotel-nats
otel-mongo-tracingOTEL_MONGO_TRACING_ENABLEDotel-mongo / v2
otel-mongo-propagationOTEL_MONGO_PROPAGATION_ENABLEDotel-mongo / v2
otel-gorilla-ws-tracingOTEL_GORILLA_WS_TRACING_ENABLEDotel-gorilla-ws

12. Hot toggle（雙向）

確認 relay 可達

已設 FLAGS_ENDPOINT（或自行 provider 在 wrapper 之前裝好），且 wrapper 已建構。

翻 flagops

# 關掉 NATS tracing
defaultRule:
  variation: disabled

# 重新打開
defaultRule:
  variation: enabled

等 provider poll

Latency ≈ relay 重讀設定 + provider poll interval。 生產預設 poll：60s。

Verify

  • NATS publish / subscribe / reply 仍執行
  • 新的 NATS PRODUCER / CONSUMER span 依預期出現或停止
Relay 可以 enable。 若 deployment 當初把 module 關掉（env 未設 / default），把 flag 設成 enabled 會在一個 poll interval 內打開 tracing——這是設計行為。 不能接受這個風險的站點：不要設 OTEL_INSTRUMENTATION_GO_FLAGS_ENDPOINT，或用 master veto / module env false（env 贏過 application option；有綁 provider 時 relay 仍贏過 env）。

13. Targeting 單一 service

otel-nats-tracing:
  variations:
    enabled: true
    disabled: false
  targeting:
    - query: service.name eq "checkout-api"
      variation: disabled
  defaultRule:
    variation: enabled
  • Zero-code 路徑會從 OTEL_SERVICE_NAME 送 service.name。
  • 自行安裝 provider：自己設 evaluation context。
  • 只有 process 級——不支援 per-request targeting。

14. Change latency

SourceDelay
Module resolution無 —— 每次操作讀當下值
Provider poll（zero-code）最多 OTEL_INSTRUMENTATION_GO_FLAGS_POLL_INTERVAL（預設 60s）
Provider poll（self-install）由你設定；GOFF 預設常為 120s

事故應變請以 poll interval 為準——兩個方向都一樣。 Poll 是帶 ETag 的 conditional GET（無變更回 304），縮短間隔成本低。

16. Common pitfalls

  1. export VAR= 或 enabled / 2 → construction error。只用 allow-list。
  2. POLL_INTERVAL=60（無單位） → 被拒；寫 60s。
  3. 自行裝 provider 卻忘了 DataCollectorDisabled: true → relay 中斷可能拖住 NATS 路徑。
  4. 先建 wrapper 再裝 provider → 那些 wrapper 永遠看不到 relay。
  5. 以為 master true 會 enable 什麼 → 不會。
  6. 以為切換是瞬間 → 以 poll interval 為準（預設最多 60s）。
  7. 以為 option 贏過 env → 相對 0.7.0 已反轉；env 贏。
  8. 拿 v0.8.0-rc.1 或 rc.2 來測 → 它們 require otel-flags v0.1.0，而模組程式碼早已不符合那個 API，consumer 根本編不起來。 請用 v0.8.0-rc.3 以後的版本。
  9. 用 openfeature.SetProvider 綁自己的 provider → 那是預設 槽位，本函式庫刻意不把它當成這些開關的 relay。請用 otelflags.SetNamedProvider。
  10. 以為啟動時連不上的 relay 就永遠死了 → 不會。provider 會被持續重新綁定直到連上 relay：第一次失敗一行 warn、之後的嘗試走 debug、恢復時一行 info。
  11. 把 debug 等級的 PROVIDER_NOT_READY 當成問題 → 那是正常的啟動視窗， 在 provider 第一次抓取之前。只有 warn 那一層才代表 relay 改不動某個開關。
